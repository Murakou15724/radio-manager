# バージョン管理ルール

Radio Manager のバージョン番号の付け方と、自動更新の仕組みについて記載する。

## バージョン番号の形式

[Semantic Versioning](https://semver.org/lang/ja/) に準じた `MAJOR.MINOR.PATCH`(例: `3.0.1`)の形式を使う。

現在のバージョン番号はリポジトリ直下の [`VERSION`](../VERSION) ファイルに保存されている。アプリはこのファイルを読み込んで画面（ヘッダーの `top-bar`）に表示する（`config/initializers/app_version.rb` → `ApplicationHelper#app_version`）。

## 各桁を上げるタイミング

| 桁 | 上げるタイミング | 誰が / 何が更新するか |
|---|---|---|
| MAJOR | 大規模な変更(UIの全面リニューアル、認証方式の変更など、アプリの使い勝手や構成が大きく変わるとき) | 開発者が判断して手動で更新する |
| MINOR | 新機能の追加(新しい画面、新しい機能の追加など) | 開発者が判断して手動で更新する |
| PATCH | 上記に当てはまらない細かい修正・バグ修正・デプロイ | **`main` ブランチへの push のたびに自動で+1される**(後述) |

MAJOR または MINOR を上げる場合は、`VERSION` ファイルを手動で編集し、それより下位の桁は `0` にリセットする(例: `3.0.7` → `3.1.0`、`3.1.4` → `4.0.0`)。

## 自動更新の仕組み

`.github/workflows/bump-patch-version.yml` が、`main` ブランチへの push をトリガーに以下を行う。

1. 直前のコミットで `VERSION` ファイル自体が変更されていないかを確認する
2. 変更されていなければ(＝人がMAJOR/MINORを手動で上げた push ではない、通常の修正・デプロイの push であれば)、PATCH の値を+1して `VERSION` ファイルを書き換え、`github-actions[bot]` の名前で自動的にコミット・pushする
3. 変更されていれば(＝直前に人がMAJOR/MINORを手動で上げていれば)、二重に上がらないよう何もしない

このワークフローが作る自動コミットのコミットメッセージには `[skip version]` という目印を含めており、そのコミット自身が再度ワークフローを起動して無限ループになることはない。

この自動更新の処理自体はアプリの画面や設定からは操作できない(意図的にリポジトリ内の設定ファイルとしてのみ存在する)。バージョンを意図的に変更したい場合は、`VERSION` ファイルを直接編集してコミットすること。
